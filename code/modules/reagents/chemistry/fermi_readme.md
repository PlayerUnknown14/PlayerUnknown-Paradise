# Как создавать реакции Ферми с точки зрения кода

## Как работает чистота

Параметр чистоты реагента (`purity`) по умолчанию задействуется только при метаболизации мобом, в случае если в `reaction_flags` рецепта не установлен один из `CLEAR_CONVERT` дефайнов. Вот блок-схема для процесса в мобе.

![image](https://user-images.githubusercontent.com/33956696/103941231-78123b80-5126-11eb-9d89-635a6b810454.png)

В общем смысле:
* Если `purity` реагента = 1: нормальная метаболизация
* Если выше `inverse_chem_val`: нормальный + нечистый реагенты
* Если ниже: конвертация в `inverse_chem`

# Как работают механики реакций

Для эффектов в начале/во время/в конце реакции см. схему ниже:

![image](https://user-images.githubusercontent.com/33956696/103941281-88c2b180-5126-11eb-8740-207dc9bb830d.png)

Пояснение:

`holder.dm` теперь настраивает реакции, а `equilibrium.dm` запускает их. `holder` обрабатывается, когда есть список реакций, а все расчёты выполняет `equilibrium`. По сути, он хранит список объектов для запуска. Прок `Handle_reactions()` используется для обновления списка реакций, с проверками в начале, чтобы предотвратить ненужные обновления.

#### Обнаружение реакции:

- Если это `REACTION_INSTANT`, то используется метод, похожий на старую механику.
- Если нет, то тогда настраивается `equilibrium`, который проверяет допустимость создаваемой реакции.
- Если она допустима, то вызывается `on_reaction()`.
- Если температура реакции превышает `overheat_temp`, вызывается `overheated()`
- Когда `equilibrium` обнаруживает невалидность реакций, им присваивается флаг удаления, и `holder` удаляет их.
- Если есть список реакций, то `holder` начинает обработку.

#### Когда `holder` обрабатывается:

- Каждый `equilibrium` обрабатывается, управляя своей собственной реакцией. На каждом шаге обрабатываются все реакции.
- В начале `equilibrium` проверяет свои условия и рассчитывает, сколько он может сделать.
- Он проверяет температуру, реагенты и катализаторы.
- При перегреве вызывается `overheated()`
- При слишком низкой `purity` вызывается `overly_impure()`
- Рассчитывается отклонение от оптимального pH и температуры, которые коррелируют с чистотой и объёмом результата.

#### Как `holder` прекращает реакцию:

Когда одна из проверок в объекте `equilibrium` не проходит, он помечается для удаления. `holder` обнаружит это и вызовет `reaction_finish()`, который удалит данный `equilibrium`, завершив связанную с ним реакцию.

## Рецепты и механики обработки

Ниже рассматриваются различные переменные для реакций. Их можно редактировать и устанавливать для каждой `chemical_reaction` отдельно.

### Как устанавливаются температурные диапазоны и как определяется скорость реакции

Скорости реакций определяются текущей температурой `holder`'а реагентов. Связанные с этим переменные:

```dm
/datum/chemical_reaction
    var/required_temp			= 100
    var/optimal_temp			= 500			// Верхний предел для вышеуказанного
	var/overheat_temp 			= 900 			// Температура, при которой реакция взрывается - если любая реакция настолько горячая, она вызывает overheated()
	var/temp_exponent_factor 	= 2         	// Насколько резкая экспоненциальная кривая температуры (в степени значения)
	var/rate_up_lim 			= 20			// Оптимальная/максимальная скорость, возможная при идеальных условиях
```

Объём получаемого реагента основывается на `required_temp`, `optimal_temp`, `overheat_temp` и `temp_exponent_factor` рецепта. См. ниже:
![image](https://user-images.githubusercontent.com/33956696/104081088-5e571e00-5224-11eb-8834-87aa36b3e45f.png)

Ось y — это нормализованное значение роста, которое затем умножается на `rate_up_lim`. Видно, что температуры ниже `required_temp` не дают результата (реакция не начинается, а уже идущая реакция останавливается). Между `required` и `optimal` находится область, которую определяет `temp_exponent_factor`, поэтому в этом случае значение в степени 2, что вызывает экспоненциальный рост. Между `optimal_temp` и `overheat_temp` находится оптимальная фаза - где коэффициент скорости равен 1. При температуре ещё выше реакция продолжится, но будет вызывать `overheated()` каждый тик. В настоящее время эффект `overheated()` по умолчанию — уменьшение выхода продукта (т.е. реакция проходит быстрее, но производит меньше реагента).

`rate_up_lim` — максимальная скорость, с которой реакция может идти при оптимальной температуре, т.е. с коэффициентом скорости 1. Так, в нашем примере температура в 500 и более будет производить 10 юнитов, а температура в 400 будет производить примерно 4 юнита за шаг.

### Как задаются диапазоны pH и что механика pH вообще делает

Оптимальные диапазоны pH устанавливаются для каждого рецепта отдельно.

Конкретный рецепт определяется параметрами датума `chemical_recipe`. Ниже приведены переменные, связанные с pH:

```dm
/datum/chemical_reaction
	...
	var/optimal_ph_min 			= 5         	// Наименьшее значение pH, при котором pH = 1 для реакций на основе pH ("фаза плато")
	var/optimal_ph_max 			= 9	        	// Наибольшее значение для вышеуказанного
	var/determin_ph_range 		= 4         	// Насколько далеко pH будет реагировать, давая место для примесей (экспоненциальная фаза)
	var/ph_exponent_factor 		= 1         	// Насколько резкая экспоненциальная кривая pH (в степени значения)
	var/purity_min 				= 0.15 			// Если чистота ниже 0.15, вызывается overly_impure(). Кроме того, если конечная чистота продукта ниже этого значения, продукт будет на 100% преобразован в failed_chem реагента. Ставьте 0 для отключения этого
```

Для этой реакции по умолчанию кривая выглядит так:
![image](https://user-images.githubusercontent.com/33956696/104081030-0fa98400-5224-11eb-822e-ffc614799ddc.png)

Ось y - это чистота синтезированного за тик продукта. Она рассчитывается на основе суммарного pH `holder`'а для каждого тика в реакции. Допустим, в нашей реакции есть 10 юнитов продукта с чистотой 1, и для за шаг мы произвели ещё 10 с pH = 3. Согласно кривой, чистота последних 10 единиц = 0.5. Таким образом, мы добавляем 10 единиц с чистотой 0.5 к 10 единицам с чистотой 1, в результате чего получится 20 единиц продукта с итоговой чистотой 0.75. (Отметим, что чистота используемых в реакции реагентов также изменяет чистоту продукта).

Если вы разрабатываете реакцию, вы можете задать оптимальный диапазон между `OptimalpHMin` и `OptimalpHMax` (5 - 7 в нашем примере) и детерминированные области (неоптимальные), определяемые переменной `ReactpHLim` (5 - 4, 9 + 4, то есть два диапазона [1, 5] и [9, 13]). Чистота в этих областях экспоненциальна, поэтому если вы установите `ph_exponent_factor` в значение 2, то кривая будет экспоненциально расти, но поскольку наш `CurveSharpph` = 1, она линейна (по сути, вам нужно нормализовать диапазон в детерминированной области, затем возвести его в степень `CurveSharppH`).

Наконец, значения pH вне этих диапазонов предотвратят начало реакций. При этом, если уже активная реакция выйдет за пределы диапазона, чистота продукта для каждого шага будет 0 (сама реакция не будет остановлена). И да, вы можете создать реакцию без детерминированной или оптимальной фазы, если хотите.

Стоит отметить: если в процессе реакции ваша чистота падает ниже `PurityMin` реакции, она вызовет функцию `overly_impure()` - которая по умолчанию уменьшает чистоту всех реагентов в колбе. При этом, если итоговая чистота продукта в конце реакции ниже `PurityMin`, то продукт преобразуется в другой реагент, определенный переменной `failed_chem` в датуме реагента.

По умолчанию `PurityMin` равен 0.15 и его довольно сложно провалить. Однако все вышеперечисленное гибко настраивается, на случай если вы хотите разработать свою уникальную реакцию.

### Условные изменения в датуме реагента за тик

```dm
/datum/chemical_reaction
	...
	var/thermic_constant		= 1         	// Изменение температуры за 1 единицу синтеза
	var/H_ion_release 			= 0.01       	// Изменение pH на за 1 единицу синтеза
```

`thermic_constant` - это то, насколько температура изменяется за каждую синтезированную единицу продукта. Так, реакция с вышеуказанными параметрами увеличит температуре `holder`'а на 10K после синтеза 10 единиц.

`h_ion_release` - это то, насколько изменяется pH на каждую произведенную единицу. Следовательно, 10 синтезированных единиц увеличивают pH увеличится на 0.1. Во время реакции это единственный фактор изменения pH - добавление/удаление реагентов, связанных с реакцией, не окажет эффекта. Однако реакции, происходящие в колбе параллельно, изменят pH, как и удаление/добавление реагентов вне реакции.

### Флаги реакций

`reaction_flags` используется для установки дефайнов, переопределяющих поведение реакции. К примеру:

```dm
#define REACTION_CLEAR_INVERSE  // Преобразование продукта реакции в инверсивный реагент, если чистота достаточно низкая (по умолчанию работает только при метаболизации мобом)
#define REACTION_INSTANT        // Используется для создания мгновенных реакций
```
# Реагенты

Новые переменные для реагентов:

```dm
/datum/reagent
	/// pH реагента
	var/ph = 7
	/// Чистота реагента
	var/purity = 1
	/// чистота реагента при создании (т.е. когда он добавляется к мобу и его низкая чистота делит его на 2 химиката; чистота полученных химикатов сохраняется как `creation_purity`)
	var/creation_purity = 1
	// значения нечистого химиката:
	var/impure_chem		 = /datum/reagent/impurity			// Какой химический путь создается при метаболизме как функция чистоты
	var/inverse_chem_val = 0.2								// Если примесь ниже 0.2, заменить ВЕСЬ химикат на inverse_chem при метаболизме
	var/inverse_chem	 = /datum/reagent/impurity/toxic		// Какой химикат метаболизируется, когда чистота ниже inverse_chem_val
	var/failed_chem		 = /datum/reagent/consumable/failed_reaction // какой химикат создается в конце реакции, ЕСЛИ чистота ниже purity_min рецепта
    var/chemical_flags
```

- `pH` - это врожденный pH реагента, используемый для расчёта pH реагентов в  `holder`'е при добавлении/удалении. Эта переменная не изменяется и является справочным значением. Изменяется суммарный pH `holder`'а реагентов.
- `purity` - это ВНУТРЕННЕЕ значение реагента для разделения. Оно устанавливается в 1 после разделения, чтобы реагент не делился бесконечно.
- `creation_purity` - это чистота реагента при создании. Она неизменна. Если вы пишете код, проверяющий чистоту реагента, используйте эту переменную.
- `impure_chem` - это датум реагента, создаваемого при условии, что его `creation_purity` выше `inverse_chem_val`. Когда реагент метаболизируется мобом, он разделится на это ИЛИ, если связанный `datum/chemical_recipe` имеет флаг `REACTION_CLEAR_INVERSE`, он разделится в конце реакции в `datum/reagents` holder.
- `inverse_chem_val`, если чистота реагента ниже этого значения, он на 100% преобразуется в `inverse_chem`. Если выше, он разделится на `impure_chem`. См. примечание о эффектах чистоты выше.
- `inverse_chem` - это датум реагента, создаваемого при условии, что его `creation_purity` ниже `inverse_chem_val`. Когда реагент метаболизируется мобом, он на 100% преобразуется в это ИЛИ, если связанный `datum/chemical_recipe` имеет флаг `REACTION_CLEAR_INVERSE`, он на 100% преобразуется в конце реакции в `datum/reagents`.

При написании любого кода реагента ВСЕГДА используйте `creation_purity`. `purity` сохраняется только для внутренней механики и не будет отражать чистоту при создании.

Если вы создаете нечистый реагент, я рекомендую посмотреть `impure_reagents.dm`, чтобы увидеть, как они настраиваются, и подумать об использовании `datum/reagents/impure` в качестве родителя.
